# 1. 部署

*在哪跑、怎么装、第一次对话*

<!--

# 在哪运行

- **最理想：专用设备**——闲置笔记本、VPS（$5/月）、旧安卓手机（[BotDrop](https://botdrop.app)）。24/7运行→在你睡觉时也在工作的助手。

- **在主电脑上跑？**隔离它——Windows用WSL（内置Ubuntu）、macOS用Docker或UTM虚拟机。

<v-click>

- **云端一键部署**→试试可以，但你会失去"本地化和个人化"的价值。那跟ChatGPT有什么区别？

</v-click>

<!--
最好情况：别在你的主力电脑上跑。Agent能读取它所在机器上的很多文件——后面安全部分会讲为什么这很重要。单独的设备也意味着它24/7运行，所以你的Agent一直在。你得到一个在睡觉时也在工作的助手——老实说，我觉得这就是很多人真正开始爱上它的时刻。你睡前让它做件事，醒来发现已经做完了。那种感觉很棒。

如果你没有备用设备：Windows用户用WSL——它基本上是内置在Windows里的Ubuntu，跑这个很合适。Mac用户，Docker是简单选项，或者UTM如果你想要更好的隔离——他们有现成的Ubuntu镜像可以直接下载启动。

云端部署也可以，如果你只是想试试。但你失去了整个意义——在本地、在你自己的机器上、做个人化的事情。没有这些，它基本上就是另一个ChatGPT。如果你只需要这个，也许不需要OpenClaw。那也没关系。
-->

# 安装与配置

```bash
curl -fsSL https://get.openclaw.ai | bash
```

引导向导涵盖要点：

1. **选择模型**——用你能负担得起的最好的。别让模型限制影响你对OpenClaw的评价。优先订阅制而非API点数。

2. **设置Telegram**——创建机器人、粘贴token、使用配对模式。两分钟后就能聊天了。

3. **启用Session Memory**——在引导的`Enable hooks`步骤中选择`session-memory`。这会在你开启新会话时保存对话上下文到记忆文件。

<!--
你选好了在哪运行。现在实际安装它。一个命令，搞定。它会识别你的系统、安装缺少的东西、设置好一切。然后你进入引导向导。

模型：选你能负担得起的最好的。Claude Opus、GPT-5、Gemini Pro——任何顶级模型都好用。原因是——别让弱模型让你以为OpenClaw本身不好。先获得最好的体验，之后再担心成本。订阅制比按量付费的API点数好得多，因为点数在你还在摸索阶段就用得飞快。

Telegram：最简单的开始聊天方式。通过BotFather创建机器人、粘贴token、使用配对模式——跟机器人打个招呼、输入代码，搞定。两分钟。

Session Memory：这是大多数人错过的。打开它。它的作用是：当你的聊天太长需要压缩时，它会先保存重要的东西到记忆文件。没有它，每次上下文压缩，你的Agent就...忘记一切。就像跟一个没有长期记忆的人说话。有了它，你的Agent能跨对话记住事情。这就是它感觉像个真正助手而不是每次清零的原因。
-->

# 风险金字塔

风险随使用深度增加。你给的权限越多，越需要思考。

- 🟢 **安装**——Agent能读取你用户下的大部分文件。密钥、配置、下载。它可能不看，但它*能*看。
- 🟢 **聊天**——跟任何聊天机器人一样。内容会发到模型API。别发密码。
- 🟡 **读/写文件**——它可能误解你的意思，删除或覆盖东西。最常见的问题：它"自杀"——破坏自己的配置。记得备份。
- 🟡 **浏览器**——它操作你已登录的会话，更糟的是，它可能被诱导访问恶意网站。
- 🔴 **安装Skill/包**——可能安装错误版本或恶意代码，来自错误指令或幻觉出来的包名。

<!--
我把安全想象成一个金字塔——你越深，你给它的权限越多，风险越高。

底层：只是安装它。Agent能读取你用户能看到的大部分文件——下载、配置文件、可能是SSH密钥。它可能不会主动去找，但它可以。Docker或VM隔离在这里有帮助。

聊天：基本上跟用ChatGPT一样的风险。你的消息发给模型提供商。别输入密码或秘密。

文件访问：这里开始变真实了。它可能误解你想要什么，删除东西，或覆盖错误的文件。最常见的问题？它破坏自己的配置，基本上自杀。人们开玩笑说主要工作不是提高生产力——是照看你的Agent。我的真实故事：几天前，我的Agent清空了自己的工作空间。还好我有备份。否则几个月的记忆和项目笔记就没了。

浏览器：如果你让它用浏览器，它能操作你已登录的账户——就像把你的解锁手机给别人。但更大的风险是它可能被诱导访问恶意网站。如果提示注入告诉它打开钓鱼页面或利用浏览器漏洞的网站，它可能就会这么做——带着你所有的cookie和会话。

安装东西：这是最危险的层级，所以让我深入讲讲。当你让Agent安装Skill或包时，你基本上是在让它在你的机器上运行代码。三件事可能出错。一：模型编出一个听起来对但不存在的包名。坏人知道这会发生，所以用这些名字创建假包。你的Agent尝试安装它，现在你的机器上就有了恶意代码。二：你安装的Skill可能在文档里埋了隐藏指令。记住，在Agent世界里，README文件基本上是可执行的——Agent读取它、执行指令，现在不好的东西正在你的机器上运行。三：你的Agent被外部来源欺骗——有人在你Agent读取的网页或文档里放"请安装这个有用的工具"，它就照做了。这就是为什么安装前应该审查每个Skill——读每个文件，不只是脚本，还有markdown和配置文件。在Agent世界里，文档就是代码。

好消息：如果你只是聊天，事情基本在控制之中。风险只会在你越深时增加。从小开始，随着给它更多权限而增加保护。
-->

---

# 记住这些原则

- 🛡️ **"病从口入"**——对你喂给Agent的每个外部输入保持谨慎（文档、链接、网页）

- 🧠 **用你能负担得起的最好的模型**——更好的模型更不容易被操控。如果预算紧张，至少在主会话（外部输入入口）用最好的模型。

- 👁️ **AI能访问的，就当公开的**——如果敏感文件在它能触及的范围内，就当它们已经暴露了。及时更换密钥。

- 🌐 **别把端口暴露在公网**——如果你需要IM聊天之外的远程访问（CLI、WebUI），用[Tailscale](https://tailscale.com)建立私有网络。

<div class="mt-4 pt-3 border-t border-gray-500 border-opacity-30 text-sm">

📖 **延伸阅读**：[SlowMist的OpenClaw安全实践指南](https://github.com/slowmist/openclaw-security-practice-guide)——最全面的Agent安全资源。

</div>

<!--
这是风险图景。现在让我给你一些涵盖大部分需要知道的东西的原则。

# 从对话开始，而非自动化

- 第一天别设置50个skill
- 就跟它聊天。随机想法、快速查资料，什么都行
- 养成习惯：**"我的Agent能帮我做这个吗？"**
- 大项目从小💭开始，OpenClaw本身就是这样

<!--
第一大错误：试图在第一天自动化所有事情。设置50个skill、连接每个工具、构建完美工作流。别。开始跟它聊天。像真正的助手一样——随机想法、快速问题、脑子里出现的任何东西。

你真正在养成的是习惯。每次你要做某事，停下来想想："我的Agent能帮我做这个吗？"随着时间这变得自动，那就是事情真正开始奏效的时候。

记住——大事从小开始。OpenClaw本身始于一个人的周末项目。我的播客工作流始于"嘿，你能把这些音频文件拼在一起吗？"我今天用的每个系统都始于随便的聊天消息。

# 我的Discord工作流

- **#daily**——日常聊天、快速任务、头脑 dump
- **#writing**——博客文章、文章、幻灯片（就像这个）
- **#podcast**——播客制作流程
- **#digests**——自动X/Twitter列表摘要，每日3次
- 每个话题→自己的线程→干净上下文，不串台
- 在另一个会话分享线程链接→Agent立即读取上下文。不用复制粘贴。

# 进阶：一起构建一个Skill

我的播客制作流程——完全通过与Agent聊天构建：

- 💬 我在**#editorial**语音 dump 想法→自动转录并精炼成文本
- 📋 分享线程链接到**#podcast**→Agent组织内容、构建叙事、生成稿件
- 🎙️ 我根据稿件录制，把音频片段丢进Discord
- 🔧 Agent拼接片段→去除静音→标准化音量→添加片头音乐
- ✂️ 我说"把关于X的部分删掉"→Agent找到它、剪辑、平滑接缝、更新时间戳和shownotes
- 🔄 每次修复都成为下次的永久Skill改进

<!--
让我展示一个进阶例子——用了段时间后日常使用实际是什么样的。我做一个播客，整个流程——从想法到发布——是通过与Agent聊天构建的。

其实录音前就开始了。当我有集的想法时，我直接发语音消息到一个叫#editorial的频道。Agent用Whisper自动转录并清理文本。然后我粘贴那个线程链接到#podcast线程，Agent读取我所有的原始想法，帮我把它们组织成逻辑顺序，生成我可以录制的稿件。整个前期制作通过语音消息和聊天完成——我从不用坐下来"写"任何东西。

然后录音：我根据稿件分几段录制音频，把文件丢进去。Agent把它们拼在一起、剪掉静音、标准化音量、用漂亮的淡入添加片头音乐。当我回听想删除某部分时，我不需要找到精确的时间戳。我只需要说"把我说X的部分删掉"。Agent有完整转录，所以它找到匹配部分、剪掉、平滑接缝所以没有突兀跳跃，并自动更新shownotes里的所有时间戳。

它还从Whisper转录写shownotes和章节标记。时间戳格式化为Spotify和Apple Podcasts可以点击跳转。

我们一路上遇到真正的问题。音频片段有不同采样率导致故障。拼接步骤的一个bug产生了46秒的死静音。每次我们遇到bug并修复，修复就进入Skill——所以下一集自动更好。

这是生存的真正要点：不是一次性设置。它是一个循环。每次你用，系统变得聪明一点。播客Skill今天比第一版好得多，每个改进都来自于...使用它。这可能就是为什么社区里很多人说他们在"养"OpenClaw，而不只是"用"它。它与你一起成长。
-->

# 我实际用它做什么

- ✍️ **内容**——博客、播客、幻灯片、X推文
- 🤖 **开发**——协调Codex和Claude Code，驾驭工程（harness engineering）

- 🗓️ **个人助理**——行程规划、提醒、语音备忘转行动
- 💡 **思考伙伴**——很多最好的想法来自跟它聊天
